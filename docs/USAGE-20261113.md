# 用量页面

入口：左侧「用量」、设置中的「用量」、项目标题旁「用量」。路由 `/#usage`，
项目入口使用 `/#usage?projectId=...`。没有迁移 React，也没有改变原资源 URI。

设计来源：Figma `roN4ySdKkS8eYopaKXkyFD` 的 U1–U6（节点见 upstream/manifest.json）。
延续暗色主题、四项指标、堆叠用量趋势、分布、调用明细、右侧详情与手机布局。
Bot 分布始终按项目分组，同一 Bot 的不同项目不会合并；总助单列。
真实数据取代设计示例。新增 SVG 从 Figma 原始导出保存至 web/public/assets。

## 采集与口径

- 新增 SQLite `usage_calls` 表及索引，原表不改；每次外部 HTTP 尝试前落盘。
- 完成或异常时存最终收到的 usage。累计样本替换，不相加；重试是新的尝试。
- 中断且未收到结束标记的样本仅供查看，不能当最终用量。重启中的调用标为中断，不自动重放。
- Project、Bot、Session、Run、Turn、Step、用途及实际模型随调用记录；并发上下文使用 AsyncLocalStorage 隔离。
- 执行、压缩、Bot 发起的摘要/向量调用继承所属上下文；手动后台作业归为未归属项目，不猜测多项目知识的归属。
- Chat Completions 输入包含缓存命中；命中+未命中=输入。reasoning 是输出子集，不另加。
- 任意调用缺少缓存拆分时整体命中率显示未知；已记录 Token 与缺失计数分别展示。
- 历史 assistant/message 与 context/checkpoint 事件一次性幂等回填。未保存的尝试与模型未知，不声称完整历史账单。
- 数量与尝试聚合参考固定 SHA 的 Harness token-meter（详见 UPSTREAM）；没有安装完整 Harness。
- 费用只采用用户填写的模型单价作当前页面估算，不内置设计稿示例价格，不代表实际账单。
- 余额仅访问配置了 Key 的 DeepSeek 官方账户接口，拒绝对中转地址进行推断；不记录密钥。

## 接口

- `GET /api/usage`：start/end（ISO，左闭右开）、projectId、botId、model、purpose；返回筛选后的账本和汇总。
- `GET /api/usage/detail?id=...`：调用、同一请求的重试和对应 Run 最近工具记录。
- `GET /api/usage/balance`：只读 DeepSeek 余额与查询时间，适用原有本地会话令牌验证。

## 验证

- `npm run check`：37 个模块检查通过。
- `npm test`：44 项通过，包括真实本地 HTTP fixture 下的累计样本、物理重试、并发归属、历史导入与中断恢复。
- `tests/usage-ui.mjs`：6 组原生 Chromium 导航检查通过，1440×1024 与 390×844，采用生产 CSP，无浏览器策略修改。
  覆盖空状态、缺失统计、按项目组织成员、项目筛选、明细、日期、手机布局；截图和报告在 tests/artifacts/usage。
- 本地实际账户历史记录：86 条可回填记录，均包含用量与缓存信息。DeepSeek 官方余额接口只读验证 HTTP 200。
- 未额外发起付费真实模型推理；新的采集生命周期经 HTTP fixture 验证，不能把它说成真实服务商长期任务验收。

浏览器测试依赖外部 Playwright，可使用 `PLAYWRIGHT_MODULE` 指定模块、`LEDE_TEST_BROWSER` 指定已安装 Chromium。
生产仍只依赖 Node 内置模块，不需要 npm install。

## 单次请求日志（2026-11-13 补充）

调用详情现在展示原始请求快照、逐条输入消息搜索、工具定义、请求参数、模型响应和当前
请求输出触发的工具参数/结果。新建 `usage_request_logs`（同一请求的重试共用输入快照）
与 `usage_response_logs`（每次尝试独立输出）表。快照不在列表接口返回，只在详情读取。
请求头不保存，配置中的 API Key 字符串从快照中替换为 REDACTED；详情返回时对历史
输出与工具结果也执行同样的过滤。普通业务资料保留以供分析，日志继续属于本地数据备份范围。

输入构成按所存 JSON 字符数统计，明确不是 Token 的逐段分配。服务商报告的 Token 总量
仍为唯一用量依据。优化提示依据最大输入部分、工具返回/定义占比、相同消息、重试次数、
单次缓存率提供检查方向，不自动改变提示词、工具集合或执行策略。

工具日志从该次响应的 tool-call IDs 和 Step 关联，不再显示整个 Run 最近五条工具。
工具结果是在本次模型响应之后产生的，不能计入本次输入；后续请求若带入则在后续输入中展示。
中断响应片段显式标记未完成。没有请求快照的历史记录不拼造输入；只回显已持久化的输出事件。

补充验证：46 项 Node 测试通过（含快照、密钥过滤、请求间工具隔离、中断片段），
6 组浏览器测试通过（含日志展开、搜索、HTML 文本安全展示和两种布局）。
