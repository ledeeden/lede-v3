# Bot 职责约定

总助接事与路由，负责人组织与验收，执行成员产出专业成果。身份以 Project 的 leadBotId 和会话绑定判断，不以 Bot 自填的 role 名称冒充负责人。

| 角色 | 负责 | 不负责 |
| --- | --- | --- |
| 总助 | 用户明确建项即创建项目和负责人，携原话、链接及约束 project.delegate；查找已有知识；简短汇总负责人汇报 | 自行联网研究、写项目报告、创建成员、改任务或替负责人验收 |
| 项目负责人 | 接手目标、复用/组织团队、task.create + task.dispatch、读成果证据、task.review、project.report、维护看板 | 包办专业执行、未达验收条件即结项、绕过用户停止 |
| 执行成员 | 按任务专业执行、保存完整 L2 与来源、task.submit 提交成果和限制 | 擅改项目目标、建团队、代替负责人验收结项 |

明确的主题和首个研究链接足以建项，研究范围和深度在项目内逐步细化。只有无法合理推断且会影响方向的决定才提问。总助必须分别确认创建和派发的实际回执，不能把创建负责人等同于已交接工作。

研究员采集证据，分析员分析，开发/制作员实施并验证，审查员独立核验；负责人综合和抽查。有当前 Task 时成员使用 task.submit 保存成果并进入 review；临时委派用 knowledge.create 保存后回传 URI。停止不等于可自动重试的失败，未知副作用不得重放。

实现：server/runtime/roles.mjs 提供运行时职责合同；ToolRegistry 在工具定义、直接 execute 和内核调用入口限制角色工具。旧的总助 tools=['*'] 同样受限，无需覆写用户 Bot 配置。执行成员的 task.submit 保留给窄工具配置，task.update 也不能绕过负责人结项要求。专业能力仍由 Bot 的工具配置限制。

这些是应用工作流边界，不是多用户数据隔离。负责人可读取原始来源以抽查，是否合理拆解与派发仍需真实模型质量验证。测试 fixture 验证建项/交接链路、工具拦截和账本配对，不冒充真实模型行为验收。
