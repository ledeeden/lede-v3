# 项目运转与动态页

对应 Figma `roN4ySdKkS8eYopaKXkyFD` 的 `102:7493`（项目动态 · 对话式）。

## 任务交付协议

- `task.create` 创建业务任务，可指定依赖、验收要求和 `requiredTools`。
- `task.dispatch` 用 taskId、baseRevision、request_id 派发；检查同项目、依赖、执行者和所需工具。`task_work_links` 记录 Task 与 Work 的关系，不合并身份。接纳与任务关联在同一 SQLite 事务中完成，没有异步 IO。
- Run 开始时关联任务由 queued 进入 doing。等待下游仍保留等待关系。
- `task.submit` 保存草稿知识并把任务移入 review，记录产物 URI、局限和本次 Run。入口对成员可见，但只能提交当前 Work 绑定的本人任务；只读模式禁用。不会因此开放任意知识编辑、网络或 shell 权限。
- 负责人读取产物后调用 `task.review`，用明确结论通过或退回。用户也可在动态的待处理栏、进展卡片中验收。退回后重新派发。Run 成功本身不使 Task 完成；结束而没有交付会成为明确的任务阻塞。
- 通过界面派发的交付会回传负责人；历史无 Task 关联的 Work 保持兼容，不猜测并改写旧任务。恢复已关联任务保持关联与历史记录。

## 当前状态与历史

`GET /api/project` 返回派生状态、当前重点、成员最新执行、待确认、交付物。派生状态不覆盖用户填写的业务阶段，也不把任务全部结项等同项目目标已完成。历史错误仍在进展与执行详情中保留，聊天只把最新运行错误显示为当前错误。

成果识别包含任务 outputRefs、producedBy、视图和以 report/material/deliverable 结尾的分类，兼容 research/report。既有任务全结项时显示“当前任务已结项”，而非“还没有执行任务”。

## 界面

动态采用紧凑成员状态条、可展开短消息、产物链接和可展开工具记录。底部输入默认发给负责人，可选择成员修正；修正沿既有协议同步负责人。桌面右侧显示进行中、待处理、最新成果，点成员打开独立对话；关闭返回动态。手机保留动态和输入，任务操作可从进展页进入。完整目标折叠，当前重点显示实际待办。

## 验证与边界

- `tests/project-workflow.test.mjs`：派发去重、依赖、受限成员提交、草稿持久化、验收权限、退回、失效产物、历史错误、完整模型协议回传。
- `tests/project-workflow-ui.mjs`：1440×1024 / 390px，长消息折叠、成员侧栏、交付验收、总览空状态。
- `tests/project-workflow-live.mjs <providers.json>`：明确选择后才调用真实服务商；独立临时数据库、禁用外部研究与 shell，退出清理。2026-11-13 对当前 deepseek-chat 实测：2 步、1 个保存的知识对象、Task=review、Run=succeeded。
- 真实模型的这个短链路验证不等于复杂研究质量或长时间自主运行验收。验收字段与引用不会自动判断事实真假。现有 OpenViking 结论、任务与工具配置没有批量改写，也未自动重跑研究。
- 修复 UI 重渲染在替换 DOM 前过早销毁 PDF 的竞态；文字提取期间延迟事件刷新，避免操作中销毁文档。
